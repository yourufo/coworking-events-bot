## bugfix-1 — 2026-08-04

**Исправлено:** `/add_event` зависал на кнопке «Подтвердить» и не
сохранял событие — падал с ошибкой SQLite
`table events has no column named description`.

**Причина:** файл БД (`data/coworking.db`) был создан ещё до того, как
в схему добавили поле `description`. `CREATE TABLE IF NOT EXISTS` не
трогает уже существующие таблицы — новая колонка в реальном файле
физически не появилась.

**Фикс:** при каждом старте бота теперь проверяется список обязательных
колонок и через `ALTER TABLE` дописываются недостающие, без потери
уже сохранённых данных.

PR: #2 (`bugfix-1` → `main`)

## feature-1 — команда /add_event — 2026-08-04

Реализован полный сценарий добавления события: `/add_event` запускает
пошаговый диалог — название → дата (ДД.ММ.ГГГГ) → время (необязательно,
кнопки «Добавить время» / «Пропустить») → описание (необязательно,
кнопки «Добавить описание» / «Пропустить») → экран подтверждения →
сохранение в БД. `/cancel` прерывает диалог на любом шаге.

Заодно: все тексты бота вынесены в отдельный модуль `bot/messages.py`,
бриф синхронизирован с реализацией (поле `description` в EVENTS,
обновлён сценарий, добавлены тексты шагов).

PR: #1 (`feature/add-event-command` → `main`) — ветка названа ещё до
того, как договорились об именовании `feature-N`/`bugfix-N`.
